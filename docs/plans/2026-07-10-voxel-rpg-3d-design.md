# 体素 RPG 3D 篝火议会设计

## 目标

在保留现有经典 2D 方块对局的前提下，新增可切换的 3D 森林生存营地。玩家以环绕镜头观看 8–12 名体素 NPC 围绕篝火进行狼人杀，所有规则、多人同步、身份遮罩和人类输入仍由现有状态流负责。

## 已确认决策

- 第一张地图为森林生存营地。
- 地图二“体素村庄广场”和地图三“黑暗奇幻遗迹”仅记录为后续扩展，不在本阶段实现。
- 采用 3D 篝火议会，不提供 WASD 自由移动。
- 使用 RPG HUD：任务追踪、阶段、玩家列表、日志和快捷操作覆盖在 3D 世界上。
- 使用智能跟随镜头：发言和关键事件自动聚焦；用户拖动后临时接管，后续事件触发时平滑恢复。
- 使用 React Three Fiber + Three.js；3D 模块懒加载，经典 2D 首屏不加载 3D 依赖。
- 使用原创程序化体素材质，不复制《我的世界》贴图、模型或商标元素。
- 不修改狼人杀规则引擎和多人协议。
- 不处理 Git 和 APK。

## 体验结构

3D 世界占据主画面。森林、木屋、草方块、石块、火把和动态篝火构成营地，玩家 NPC 按人数自动排成圆形。白天使用暖色太阳光和清晰远景；夜晚切换月光、篝火主光源和轻雾。当前发言者由镜头、座位光圈和头顶气泡共同标识。死亡玩家替换为墓碑；断线与 AI 托管使用独立状态标记。

HUD 左上角显示当前任务和阶段目标，顶部显示昼夜与天数，右侧显示玩家队伍，左下角显示可折叠日志，底部保留人类操作面板。点击 NPC 会把目标传给现有输入面板，但提交行动仍走原有输入解析和多人 ACK。

## 架构

- `GameRoomView` 根据持久化的 `gameViewMode` 懒加载 2D 或 3D 对局。
- `VoxelRpgRoom` 是 3D 页面组合层，只调用一次 `useGameRoomState`。
- `ForestCampScene` 负责 Canvas、森林、篝火、灯光和玩家圆阵。
- `sceneModel.ts` 提供可测试的座位坐标、角色可见描述、昼夜光照和镜头目标计算。
- `SceneDirector` 监听当前发言者和关键阶段，驱动相机补间。
- `RpgHud` 显示任务、玩家列表、日志和世界状态。
- `worldTargetAtom` 在 3D NPC 与 `HumanInputPanel` 之间传递预选目标。
- `ThreeSceneErrorBoundary` 捕获 WebGL/场景初始化错误，提供返回经典 2D 的操作。

## 隐私与状态

场景层只能接收 UI 可见模型。未知身份统一使用中性外观，不允许隐藏角色决定衣服、道具、颜色或粒子。多人访客继续使用服务器裁剪后的玩家和日志。3D 模式不得新增任何绕过 `HumanInputPanel`、`resolveHumanInput` 或 WebSocket ACK 的提交路径。

## 性能与降级

- 3D 模块通过动态 import 分包。
- 角色和环境使用低面数 BoxGeometry；重复树木和地面块优先复用几何体与材质。
- 根据现有 `effectLevel` 控制阴影、粒子和装饰密度。
- 桌面端目标 60 FPS，普通手机低效果目标不低于 30 FPS。
- WebGL 不可用或场景初始化失败时显示说明并可切回 2D。

## 验收

- 2D/3D 对局内切换并持久保存。
- 8–12 名 NPC 自动排座，当前发言、死亡、断线和 AI 托管状态正确。
- 昼夜、篝火、镜头智能跟随和手动接管可工作。
- RPG HUD 显示阶段、任务、存活人数、玩家和日志。
- 点击 NPC 可预选合法行动目标。
- 单人、房主、访客均不泄漏隐藏身份。
- 3D 失败可恢复 2D。
- 类型检查、单测、生产构建和多人 E2E 全部通过。
