# 方块狼人杀当前版本完成度审计

审计日期：2026-09-12  
审计基线：`main`，HEAD `5fb6ae79873d50c3668df1cf1cf40cb435f66991`，加上本次“移除默认模型”未提交修改。  
审计目标：判断当前版本是否达到可演示、可内测、可公开发布三个不同门槛，并记录可复现证据。

## 结论摘要

当前版本是“功能完整度较高的内测 Beta”，不是可以直接交付给普通用户的稳定 Release。

综合完成度：**约 7/10**。

- 作为视觉演示和规则引擎原型：可以使用。
- 作为配置了自己 API 的个人内测版本：基本可用，但仍需真实整局验证。
- 作为开箱即玩的公开版本：暂不通过，主要阻塞是端到端浏览器验证、真实模型整局验证和桌面/Android 发布验收。

本次已经处理的 P0 配置问题：

1. 移除已下线的 `deepseek-ai/deepseek-v4-flash` 默认模型。
2. 默认角色不再绑定隐式云模型，`llmPresetId` 初始为空。
3. 旧版本保存的该默认模型会在启动时迁移移除，不再静默回退。
4. 首页没有可用云 API、本机模型端点或远程代理时，不再直接启动 AI 对局，而是引导到模型设置。
5. Playwright 测试夹具改为显式注入测试供应商和测试模型，避免依赖产品默认配置。

## 证据分级

- **已验证**：本次命令、HTTP 探针或浏览器页面直接观察到。
- **测试验证**：自动化测试通过，但不等同于真实设备或真实第三方服务。
- **源码确认**：从调用链和实现可确认，尚未完成运行时证明。
- **阻塞**：验证没有执行到业务断言，或依赖外部环境/凭据。

## 1. 产品入口与视觉 UI

**结论：8/10，已达到可演示水平。**

已验证/源码确认：

- 首页有 AI 旁观、单人加入、多人服务器三条入口。
- 有多套人数和规则板子，筛选、阵容预览和营火启动流程完整。
- 设置中心覆盖外观、游戏规则、模型与语音、玩家分身、高级配置。
- 规则手册、历史存档、指南和调试面板均有独立入口。
- 2D 经典模式和 3D RPG 营地模式共用同一局面状态。
- 本次浏览器实测首页能够显示“请先在设置中填写可用的模型 API”，点击“点燃营火”会进入设置页，不会再直接发起失败的默认模型请求；本机端点属于允许的无云 Key 例外。

## 7. 安全、隐私与作弊边界

**结论：可信局域网熟人联机按 8/10 评估；公网/陌生用户场景仍按 6.5/10 评估。**

本审计对当前版本采用“朋友在同一可信局域网内联机”的威胁模型。该场景下，API Key 保存在本机浏览器并可能随用户明确选择的配置同步传递，属于已知且接受的运营风险，不作为当前内测阻塞项。

已验证/源码确认：

- 生产构建安全测试确认开发 NVIDIA Key 不会被打包进产物。
- 多人状态同步会隐藏其他玩家角色、私有日志和提示词。
- WebSocket 采用 session token hash，服务端校验来源并拒绝公网跨站来源。
- 配置同步默认脱敏 API Key，只有用户明确勾选才包含密钥。

已接受的局域网风险：

- API Key 通过 Jotai `atomWithStorage` 保存在浏览器 localStorage；设置导出和“含密钥”的局域网同步也可能携带密钥。
- 房间服务配置快照可能落盘到 `config-share.json`，包含密钥时应视为局域网信任边界内的敏感文件。
- 当前模型请求主要由客户端发起；在朋友可信、设备可信的局域网环境中接受该行为。

边界：

- 如果后续开放公网、陌生用户或不受控 Wi-Fi，需重新评估 API Key 传输、存储和服务端代理策略；这不是当前局域网内测的发布阻塞。

## 发布判断与优先级

### P0：公开发布前必须完成

1. 用户填写有效 API 后，跑通一整局真实 AI 对战并保存日志/截图证据。
2. 修正 `multiplayer.spec.ts`、`rpg-dialogue.spec.ts`、`voxel-3d.spec.ts` 的状态同步、瞬态浮层、语音状态和移动视口同步，重跑 Playwright E2E 至 5/5；当前最新一轮 2/5，之前运行在 4/5 之间波动。
3. 运行 Electron 打包启动验收和 Android Debug/Release 真机验收。
4. （公网版本再处理）重新评估 API Key 的传输、存储和系统钥匙串策略；可信局域网朋友联机不阻塞当前版本。

### P1：内测体验建议完成

1. 将“模型配置完整”和“模型验证成功”拆成两个状态，避免配置了失效 Key 仍显示可开局。
2. 拆分 3D 大 chunk，测量 Android 首屏时间、FPS 和内存。
3. 用旧版本真实存档做迁移回归，覆盖自定义模型、角色分身、历史归档和联机配置。

### P2：后续产品化

1. 增加无 API 的规则演示/纯人工模式，方便用户先体验 UI 和规则。
2. 完善失败后的“更换模型并重试”交互，减少退出重开的成本。
3. 补齐发布文档、版本号、变更日志和支持矩阵。
